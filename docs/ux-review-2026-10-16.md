# UX review and implementation plan — 2026-10-16

This review records eight confirmed usability defects and the implementation plan. All eight are should-fix items. They are implemented (commit `9982a52`) and verified on 2026-10-16 with the recorded synthetic browser evidence below. Verification found and fixed four gaps. This is not a formal accessibility conformance assessment.

## Scope and method

The review used UI source, task-flow tracing and existing code-generated synthetic captures. No real studies were loaded. No patient screenshots, inference or model downloads were used. No dedicated UX design skill was installed. This is a targeted usability and accessibility review, not a formal accessibility conformance assessment.

Evidence describes the pre-fix UI reviewed after commit `5c16ba1`. Line numbers are review-time anchors and can shift during implementation. The live-preview data-directory correction is separate; these findings concern how the UI explains and exposes the library. Captures from before the fixes are historical evidence; the refreshed synthetic captures in `docs/assets/` show the verified UI.

## Severity and decision

- **High:** blocks or seriously misdirects a primary task.
- **Medium:** causes confusion, loss of workflow state or an accessibility barrier.
- **Should fix:** included in this implementation scope.
- **Later:** enhancements outside these eight findings; not required to claim these fixes verified.

## Ranked findings

### UX-01 · High · Study discovery looks like a demo-only tool

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence; two gaps fixed during verification.

**Evidence:** `src/thoraxbench/api/app.py:184–213; src/thoraxbench/api/static/app.js:125–130,332; src/thoraxbench/api/templates/index.html:35–41,59`

The library is a flat selector. It has no source groups, search, count or refresh action. Dataset index/split failures are skipped without a library explanation. The empty viewer suggests only a synthetic demo. A user cannot distinguish an empty development library from an unavailable index or a wrong configured data directory.

**Action:** Show a library summary. Separate the synthetic demo from indexed development studies. Add search and refresh. Explain unavailable sources with safe setup and recovery instructions. Do not expose sealed studies or bypass indexing and split guards.

**Acceptance checks:**

1. Use mocked inventory with a demo and several development studies. Confirm that both sources are obvious and searchable.
2. Use empty and unavailable-source responses. Confirm that the page explains the difference and offers a recovery action.
3. Refresh the library. Confirm that a valid selected study stays selected by identity, not by list position.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui.py::test_library_search_groups_recovery_and_mobile_progression` — demo and two development datasets appear as separate option groups with counts; search and dataset filter narrow the list; an empty filter result disables Run.
- Check 2: `tests/e2e/test_web_ui_acceptance.py::test_ux01_empty_unavailable_library_and_identity_refresh` — empty inventory, `unavailable` and `ready (0)` sources show distinct translated explanations (EN/DE); refresh is the recovery action and then lists the new studies. `tests/integration/test_api.py::test_library_status_explains_missing_and_unavailable_sources` covers the server statuses `split_required`, `not_indexed` and `unavailable`.
- Check 3: both tests above refresh a reordered library; the selection follows study identity.
- Fixed: a refresh that removed the selected study could keep its stale list position; the empty-library text suggested only the demo; every search keystroke reset the slice position. Refresh and search now keep study and slice when the identity is unchanged.

### UX-02 · Medium · Mobile layout puts the viewer before the first step

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence.

**Evidence:** `src/thoraxbench/api/static/app.css:5, mobile viewer-panel order rule; docs/assets/ui-mobile.png`

The mobile rule moves the large viewer above the study and model controls. The first action falls below the initial screen. Visual order also differs from the DOM and numbered workflow.

**Action:** Keep study selection before the viewer on narrow screens. Use a compact viewer or compact study controls. Keep visual order and keyboard order consistent.

**Acceptance checks:**

1. Use the synthetic demo at 390 px width. Confirm that study selection appears before the viewer.
2. Use keyboard navigation. Confirm that focus follows the visible task order.
3. Check both languages and themes. Confirm that text and controls fit without page-wide horizontal scrolling.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui_acceptance.py::test_ux02_mobile_visual_and_keyboard_order` and `tests/e2e/test_web_ui.py::test_library_search_groups_recovery_and_mobile_progression` — at 390 × 844 the study panel, viewer and model panel appear in that order; the search field is in the first viewport.
- Check 2: the same test tabs from the study search to Run; focus reaches study selection, slice slider, model selection and Run in the same order as their vertical positions.
- Check 3: parametrized for English/light and German/dark, then toggled through the other two combinations with a result table visible; no page-wide horizontal scroll in any combination.
- Cleaned up: the superseded `order:-1` mobile rule and its `!important` override were removed.

### UX-03 · Medium · Main results hide educational severity and review context

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence.

**Evidence:** `src/thoraxbench/api/templates/index.html:70; src/thoraxbench/api/static/app.js:188–201; src/thoraxbench/reports/html_report.py:176–210; docs/assets/ui-results.png`

The main table shows finding, presence, score, side and size in provider order. Positive findings can appear below negatives. Educational severity and review context exist in the offline report but are absent from the main review table.

**Action:** Show present and uncertain findings before not-detected findings. Reuse educational severity and review context in the main result. Provide a clear route to the detailed report and evidence. State that severity describes general reference context, not patient triage or a validated finding.

**Acceptance checks:**

1. Use mocked present, uncertain, not-detected and unknown labels. Confirm stable grouping and safe unknown handling.
2. Confirm that an absent or low-rated finding never implies that no review is needed.
3. Confirm that an abstention has no invented severity and that downloads remain available.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui_acceptance.py::test_ux03_grouping_unknown_labels_and_abstention_downloads` — present findings sort before uncertain, then not-detected findings, in stable provider order; unknown labels render as escaped text.
- Check 2: the same test supplies a mismatched severity for a not-detected finding; the table still shows “—”, and the visible caution states that severity is not advice for this study. `tests/e2e/test_web_ui.py::test_translated_findings_and_education_require_explicit_presentation` shows that severity needs explicit server presentation.
- Check 3: an abstention with downloads shows “No prediction”, no severity, and enabled JSON/report/HTML links. `tests/unit/test_ui_presentation.py` covers the server-side presentation rules.

### UX-04 · Medium · Model setup is detached from model selection

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence; one gap fixed during verification.

**Evidence:** `src/thoraxbench/api/static/app.js:132–143; src/thoraxbench/api/templates/index.html:43–50,63`

Unavailable model options are disabled. Their setup instructions sit in a collapsed section below the workspace. The heuristic-only explanatory note stays visible when a vision model is selected.

**Action:** Place a contextual setup action beside model selection. Open the matching model setup instructions. Show adapter-specific help. Keep downloads explicit and retain terms acknowledgement, hardware guidance and provider access gates.

**Acceptance checks:**

1. Use mocked unavailable Ollama and HTTP-service models. Confirm a clear route from selection to the correct setup guidance.
2. Confirm that a vision selection does not display heuristic-only help as its own configuration.
3. Confirm that opening setup starts no download. Require the terms checkbox and an explicit download action.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui_acceptance.py::test_ux04_selection_leads_to_matching_setup_without_download` — selecting an unavailable HTTP-service or Ollama model shows a setup hint; the nearby setup button opens and focuses that model’s row with adapter-specific guidance.
- Check 2: the same test checks the input note for heuristic, HTTP-service and vision selections; the heuristic-only text appears only for the heuristic.
- Check 3: opening setup sends no pull request; the download button stays disabled until the terms checkbox is checked, and no request occurs before the explicit click. `tests/e2e/test_web_ui.py::test_model_download_requires_terms_and_reports_actual_layer_bytes` covers the explicit download.
- Fixed: unavailable models were disabled options, so selection could not lead to their setup row. They are now selectable; Run stays disabled until the model is available.

### UX-05 · Medium · About navigation discards the analysis session

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence; one addition during verification.

**Evidence:** `src/thoraxbench/api/templates/index.html:19–20; src/thoraxbench/api/static/app.js:328–332`

About uses full-page navigation. Returning to Analysis rebuilds study/model inventory but does not restore the result, comparison or download links. Leaving during a request also loses its visible progress; navigation does not establish that the engine stopped.

**Action:** Keep About within the current page session, or preserve analysis state during navigation. Keep the selected study, completed results and downloads. Explain the effect before leaving an active request. Do not claim that page navigation cancels inference.

**Acceptance checks:**

1. Complete a synthetic mocked analysis. Open About and return. Confirm that selection, results and downloads remain.
2. Repeat during a mocked delayed request. Confirm that the user can return to its state without starting a duplicate request.
3. Confirm that no patient data or raw model response is added to persistent browser storage.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui.py::test_about_history_preserves_pending_analysis_and_result_context` and `tests/e2e/test_web_ui_acceptance.py::test_ux05_session_notice_selection_and_storage` — after About and back (links and browser history), study selection, result context and download links remain.
- Check 2: both tests leave during a held request; returning shows the running state, and exactly one analysis request was sent.
- Check 3: `sessionStorage` is empty; `localStorage` holds only language, theme and numeric duration history, without study identifiers or model text.
- Added: a translated status notice on other pages while a request runs. It states that switching pages neither cancels nor repeats the request.

### UX-06 · Medium · Delayed tooltips cannot be hovered and share one description

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence; one gap fixed during verification. Values kept: 650 ms show delay, 180 ms hover grace.

**Evidence:** `src/thoraxbench/api/static/app.js:45–88`

The tooltip closes when the pointer leaves its trigger, including movement toward the tooltip. Every trigger also references one mutable description element. Help can disappear while being read or expose the wrong description when focus changes.

**Action:** Allow pointer travel between the trigger and tooltip. Keep Escape dismissal and the visual delay. Give each trigger stable accessible help. Keep critical instructions visible without requiring a tooltip.

**Acceptance checks:**

1. Hover a trigger. Confirm that the tooltip appears after the configured delay and remains while moving onto it.
2. Press Escape. Confirm dismissal without moving focus. Confirm that a later interaction can show help again.
3. Tab between two controls. Confirm that each exposes its own help text without a stale description.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui_acceptance.py::test_ux06_hover_grace_escape_and_tab_help` — hidden at 649 ms, visible at 650 ms; pointer travel through the gap and onto the tooltip keeps it; after leaving, it is still visible at 170 ms and hidden at 190 ms. `tests/e2e/test_web_ui.py::test_help_descriptions_are_stable_and_tooltip_is_hoverable` also covers hover persistence.
- Check 2: Escape hides the tooltip without moving focus; small pointer movement on the same trigger does not reopen it; leaving and re-entering shows help again after the delay. `tests/e2e/test_web_ui.py::test_tooltip_delay_cancels_on_leave_blur_switch_and_escape` covers cancellation on leave, blur, switch and Escape.
- Check 3: `tests/e2e/test_web_ui_acceptance.py::test_ux06_tab_between_controls_exposes_own_help` — Tab and Shift+Tab between two controls show each control’s own text; the accessible description equals the visible tooltip. Each help key has its own description element.
- Fixed: after Escape, any pointer movement on the same trigger reopened the tooltip; leaving the tooltip hid it immediately instead of using the grace period.

### UX-07 · Medium · Old results look current after settings change

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence.

**Evidence:** `src/thoraxbench/api/static/app.js:192–201,208–210`

Changing the model or requested source-slice count updates setup and the forecast but leaves the previous result and downloads visible. The result identifies its model, but does not clearly distinguish completed-run settings from the current selection.

**Action:** Show the completed-run configuration beside the result. Mark it as a previous run when current settings differ. Preserve its downloads and identity. Clear the marker only when settings match or a new result completes.

**Acceptance checks:**

1. Complete a mocked run. Change the selected model, then the source-slice count. Confirm that the old result is clearly marked.
2. Confirm that the completed-run configuration stays unchanged and its downloads refer to that run.
3. Return to the original settings. Confirm a consistent state without rerunning inference.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui_acceptance.py::test_ux07_model_and_target_changes_mark_previous_result` — changing the model, then the source-slice target, shows the translated previous-settings marker. `tests/e2e/test_web_ui.py::test_about_history_preserves_pending_analysis_and_result_context` covers the target alone; `_check_comparison_preserved_after_study_change` covers study changes and comparisons.
- Check 2: the result context text, model metric and download link stay unchanged while settings differ.
- Check 3: restoring the original settings hides the marker; only one analysis request was sent.

### UX-08 · Medium · Finding names remain English in the German interface

**Decision:** should fix. **Status:** verified 2026-10-16 with recorded test evidence.

**Evidence:** `src/thoraxbench/api/static/app.js:198,243`

Both finding tables turn canonical identifiers into English text by replacing underscores. Presence and side are translated, but the finding names are not. These table cells are interface text; generated research reports are intentionally English.

**Action:** Translate supported finding display names in both tables. Keep canonical identifiers available as secondary reference text. Use a safe fallback for unknown labels. Leave generated research reports English.

**Acceptance checks:**

1. Switch to German for mocked individual and comparison results. Confirm that known finding names translate in both tables.
2. Switch back to English. Confirm consistent names and unchanged underlying identifiers and scores.
3. Supply an unknown label. Confirm escaped fallback text without breaking the table.

**Verification evidence:**

- Check 1: `tests/e2e/test_web_ui.py::test_translated_findings_and_education_require_explicit_presentation` (individual table) and `tests/e2e/test_web_ui_acceptance.py::test_ux08_comparison_names_translate_and_identifiers_stay` (comparison table) — German names appear with the canonical identifier as secondary text.
- Check 2: switching back to English restores the English names; identifiers and score cells are identical before and after.
- Check 3: unknown labels containing markup render as literal text in both tables, without injected elements. `tests/e2e/test_web_ui.py::test_missing_confidence_is_uncertain_and_model_text_is_escaped` covers the individual table.

## Research limitations and later work

This is a self-made experimental research tool. It does not provide medical advice from a qualified healthcare professional. Its available knowledge and models may be incorrect, incomplete or misleading. Do not use its findings for diagnosis or treatment decisions.

The eight defects concern usability. Fixing them does not improve model detection accuracy, establish calibration or validate severity. A model may abstain, omit a finding or produce unsupported findings. Scores are uncalibrated and are not directly comparable across model families. Model agreement is not accuracy. “Not detected” never establishes that no review is needed. Educational severity is general reference context, not patient-specific urgency.

Keep browser elapsed time separate from engine-stage timing. Rough wait estimates remain workstation guesses or local request-history estimates, not progress percentages or promised deadlines. Keep errors, unavailable models and abstentions explicit. Keep exports offline, escaped and inside ignored results directories. Never add real patient captures to Git.

Later work can include moderated usability sessions and a wider assistive-technology audit. These require a separate scope and evidence. They are not a reason to defer the eight should-fix items.

## Guidance used

- [W3C: Content on Hover or Focus (1.4.13)](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html). Additional hover/focus content should be dismissible, hoverable and persistent. This informs UX-06.
- [W3C: Labels or Instructions (3.3.2)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html). Give users the labels and instructions needed to enter information. This informs library and model setup guidance.
- [W3C: Status Messages (4.1.3)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). Expose relevant status changes to assistive technology without requiring a focus change. Use this when verifying refresh, completion and failure messages.

The W3C Understanding documents inform this review. They do not certify this application.
