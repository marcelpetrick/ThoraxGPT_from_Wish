## Direction

The project foundation is sound: patient-level sealing, loopback guards, schemas, adapters,
provenance and the scoring/calibration libraries match Vision §2, §11–§17 and §24.

The delivery order drifted. Vision §1 defines the first release as a benchmark and
experimentation framework. The last three feature commits extended the interactive UI.
`thoraxbench.scoring` and `thoraxbench.calibration` are imported only by their own unit
tests. No pipeline consumes the indexed reference labels, and no measured result exists.

Correction (recorded in `docs/plan.md` → *Priority*):

1. Freeze UI feature work after v0.2.0. Accept only fixes and documentation.
2. Build WP8 next: development index → analysis → structured parse → scoring → report.
3. Produce a reference-scored heuristic baseline on the development split (WP11). Label
   it a pipeline baseline, not model accuracy.
4. Run MedGemma/VLM experiments through the same runner when a local Ollama server is
   available. Keep the sealed holdout untouched until a configuration is frozen.

standalone installation with external model configurations and manifests. Do not advertise
