01 / PREFLIGHT

Install. Verify. Start locally.

Use a terminal on the computer that will run the software. The commands below assume a source checkout and uv. Replace the example path with your checkout path. If uv is missing, follow the official uv installation instructions first.

  1. Open the repository directory.
    cd /home/mpetrick/repos/ThoraxGPT_from_Wish
  2. Install the locked Python environment.
    uv sync --frozen --all-groups

    Python 3.14 or newer is required. uv can provision the requested Python environment. Initial installation needs package access; inference stays local.

  3. Check the installed command.
    uv run thoraxbench --version
uv run thoraxbench --help

    Expect a version, the research disclaimer, and the command list.

  4. Start the workbench.
    uv run thoraxbench serve

    Leave this terminal open. Open http://127.0.0.1:8000 on the same computer.

Checkpoint: The “Analyze one study” page appears in English and light mode. The page shows the research disclaimer. A new installation may have no studies yet. This is expected.

Required for the demo

A supported Python environment, the locked dependencies, a browser, and enough free disk space for synthetic data and outputs.

Optional for vision models

A local Ollama installation and compatible model weights. The deterministic heuristic-hu baseline works without them.

Port 8000 is already in use

uv run thoraxbench serve --port 8001

Open http://127.0.0.1:8001. The server binds to loopback. LAN access and remote inference are not supported in this MVP.

02 / NORMAL PROCEDURE

Complete your first browser run.

Create demo → Inspect study → Run locally → Review → Export
  1. Select “Create synthetic demo”.

    Expect a synthetic study with 64 axial slices. It contains simulated nodule and fluid-density regions. The images contain no patient data.

  2. Inspect the study viewer.

    Move the slice slider. Use the Left and Right arrow keys when the slider has focus. Change the display window to Lung, Mediastinum, Bone or Abdomen. Window changes affect the viewer only.

  3. Select “heuristic-hu” as the model.

    This baseline uses HU-volume measurements. It sends no rendered images to a vision model. The image-count control does not affect its predictions.

  4. Select “Run analysis locally”.

    Wait for a completed result or explicit failure/abstention. “Job elapsed (server clock)” shows time since the worker started, including loading, inference and reporting. It differs from recorded “Engine stages”. Expect synthetic nodule and effusion findings.

  5. Read the status before you read the findings.

    Check Input QC, model image assessment, abstention reason and the finding table. These checks are separate. A sampled-image negative cannot exclude findings elsewhere in the study. Follow the interpretation checklist on the next page.

  6. Select “Open HTML in new tab”.

    Inspect findings and embedded images in the new tab. Use “Download HTML” for an offline copy. Also save JSON for structured output and “Download report” for Markdown.

Checkpoint: The saved “Download HTML” copy opens after you stop the server. Direct review links need the running server. It needs no external images, fonts, scripts or internet access. Missing evidence references remain explicit.

Optional: compare configured research models

Enable “Compare configured research models”, then select “Compare local models”. Available detector and heuristic baselines, MedGemma Q4/Q8, Gemma 3 and the Qwen3-VL no-think control run sequentially; unavailable models are skipped. “Batch progress” shows the current model, not inference percent. Save per-model downloads and “Download comparison HTML”. See model setup and rough wait estimates before a longer run.

Keyboard help and preferences

Use Tab to reach controls and help-bearing fields. Focus or hover shows translated help after a short delay; you can move the pointer onto it. Escape dismisses it until you move to another control. The language switch selects English or German. The theme switch selects light or dark. Both choices persist in this browser. Reports and prompts remain English. About lists attribution and licenses, plus GitHub access for forks and contributions.

Privacy checkpoint: A downloaded report contains images and research identifiers. Keep real-study exports in controlled local storage. The browser may save downloads outside the repository; manage those copies as sensitive data.

03 / LOCAL INPUT

Open a DICOM folder on this computer.

Use an existing DICOM CT study you are permitted to process. Leave its source folder in place. Opening a folder does not copy files, download a model or start inference.

  1. Open “Analyze one study”.

    Find “Open local DICOM folder” under “Choose a study”. The existing indexed study library remains available.

  2. Enter the folder.

    Drop an absolute folder path or local file:/// link into the folder area to queue opening. You can paste its absolute path and select “Open folder” instead. If the browser hides the dropped folder's path, use “Browse folders”. Navigate in the in-app picker and select “Open selected folder”.

  3. Wait for the folder job.

    The shared processing queue checks the folder and loads an eligible CT series. You can cancel queued work. A running stop takes effect at a stage boundary; the loading call may finish first.

  4. Inspect the selected study.

    Check its slice count, move the slider and select a display window. Choose a model only when you are ready to run a separate analysis.

Checkpoint: A source slice appears. The local folder is selected and labelled for this server session. It is not automatically part of the frozen development cohort. At most 16 local registrations are retained.

Recover from an unavailable folder

Select the folder containing the DICOM CT series. Individual JPG/PNG images and archives are not supported. Check local permissions if the folder cannot open. Wait for the Local dataset selection and a visible viewer image. Run is blocked while loading or when input is unusable. Read input QC before running. Select “Details” on warnings or failures and download diagnostic JSON with its trace ID before retrying. Missing file extensions are supported. Unreadable headers are counted separately from selected slices. If Run stays disabled, the line below it names the reason. Never bypass a sealed-data refusal by copying or renaming a study.

Know what is retained

Source files stay in place. Local registrations and jobs live in server memory and disappear on restart. Absolute paths are not saved in browser storage or job snapshots. Directory browsing displays the current path locally; this is not an anonymity guarantee. Inspect outputs before sharing.

See the folder procedure for browser limitations and access checks. Browser folder APIs may expose only relative names, so the app does not guess full paths or upload file bytes.

04 / RESULT REVIEW

Inspect claims before conclusions.

Check every claim against evidence. The software cannot establish health, care needs or a diagnosis.

Read firstWhat it meansOperator action
CompletedThe engine returned output. This does not validate it.Inspect QC, findings, evidence and provenance.
Abstained / failedNo usable research reading is available.Read the reason. Preserve the failed run. Do not interpret it as “nothing found”.
Present / not detected / uncertainThe model's reported presence status.Treat negative and uncertain output as fallible.

Severity and “should this be checked?”

The reference scale runs from incidental → low → moderate → high → critical. Typical attention uses routine, soon, urgent, emergency. These describe general reference knowledge for a reported label. They do not establish the severity or urgency of an actual person's condition.

No automatic clearance: An absent, low-rated, unknown or uncertain finding does not establish that no professional review is needed. The tool cannot answer whether a person should be checked. Its output is not advice from a healthcare practitioner.

Check image evidence

  • Vision-model reports show the actual prepared input images. Image 1 is the first model image. A sampled image set may miss other parts of the study.
  • Heuristic reports show illustrative source-slice previews. Their source indices start at 0; they are not vision-model inputs.
  • An evidence link is a reported association, not verified localization or a segmentation. Invalid or missing references must remain unresolved.

Compare models without implying consensus

Compare each model column by finding, status and uncalibrated score. Keep abstentions, failures and skipped models visible. Agreement is not validation; disagreement is not an accuracy ranking. Use each model’s downloads to inspect its own images and provenance. A combined offline HTML report preserves the comparison and individual evidence reports.

Check reproducibility

Save JSON for original responses, QC, hashes and provenance. “Job elapsed (server clock)” covers processing time for the job; “Current model elapsed” times the active model. “Engine stages” exclude loading and reporting. Timers do not measure inference progress. Synthetic runs and transport tests do not establish patient accuracy.

05 / COMMAND-LINE PROCEDURE

Repeat a run and save its artifacts.

Run these commands from the repository root. Keep the working directory unchanged between steps. These examples use only synthetic data.

  1. Create a fresh synthetic study.
    uv run thoraxbench demo-data data/demo/manual
  2. Run the deterministic baseline.
    uv run thoraxbench analyze data/demo/manual \
  --model heuristic-hu \
  --output data/results/manual/result.json \
  --report data/results/manual/report.md \
  --html data/results/manual/report.html
  3. Open the saved HTML file.

    Open data/results/manual/report.html in your browser. Inspect the matching JSON and Markdown files in the same folder.

Checkpoint: A successful run returns exit status 0. A failed run or abstention returns a nonzero status. When a result exists, saved artifacts explain the abstention. Failures before result creation may produce only an error message.

Optional: run a local vision model

First check availability. A configured model is not necessarily installed, licensed for your intended use, or accurate.

uv run thoraxbench models
uv run thoraxbench analyze data/demo/manual \
  --model medgemma1.5-q4 --n 16 --label pulmonary_nodule \
  --output data/results/manual/vision.json \
  --report data/results/manual/vision.md \
  --html data/results/manual/vision.html

Q4/Q8 use P5 schema-v2: 16 uniform raw axial images at 896 pixels, without coronal/MIP views or heuristic cues. The UI overrides the requested count; its four-image default stays sparse. These are completion/input fixes, not established recognition readiness.

The model must exist in local Ollama. Runs may take minutes. Truncation, invalid responses or unsuitable inputs can cause abstention.

Available overrides

--model selects a configured model. --prompt selects P0–P5; P5 uses a bounded schema, IMAGE k captions and no heuristic context. Repeat --label for focused labels. --strategy and --n override slice sampling. The browser permits 1–16 slices. thoraxbench coverage checks calibration reference coverage. Read uv run thoraxbench analyze --help for all options.

HTML output must be inside the configured data directory's results/ folder. Destinations or symlinks that escape that folder are rejected before inference. JSON and Markdown examples also stay inside ignored results storage.

07 / MODEL SETUP & WAIT ESTIMATES

Install explicitly. Expect variable waits.

Select the unavailable model in “Model”, then select “Set up local models”: the setup table opens at that model’s row, and Run stays disabled until it is available. Opening setup starts no download. Alternatively open Model availability & setup. Check availability, adapter, license and provider information. “Available” means the local runtime responds; it does not establish accuracy, GPU capacity or useful predictions.

Check actual inputs: anatomy sampling preserves landmarks and can exceed the image target. Coronal views can add images. Inspect prepared previews/counts. Wait estimates use the requested count and remain guesses. A strict small-image selection uses uniform sampling without added views.

Normal CLI setup: automatic pull on run

After reviewing the publisher’s terms, run this from the repository root. Ollama downloads missing weights and opens chat:

ollama run medgemma1.5:4b-it-q4_K_M

Enter /bye. Run ollama list. Select Refresh model availability. Use the YAML tag, not app ID medgemma1.5-q4. For download only, use ollama pull medgemma1.5:4b-it-q4_K_M. See Ollama CLI reference. App analysis does not auto-pull.

Optional browser download

Prerequisites: running loopback Ollama, network access and enough space in its model store. Weights are stored by Ollama, outside this repository’s data folder.

  1. Open “Model terms”.

    Check the publisher’s terms and any access requirements.

  2. Check “I reviewed and may comply with the applicable model terms”.

    Acknowledge this only when the terms permit your use.

  3. Select “Download model weights”.

    The app asks local Ollama to pull that configured tag. Downloads never start automatically.

  4. Inspect “Model download”.

    “Active layer bytes” reports actual current-layer bytes. It can reset between layers; it is not a whole-model percentage. Analysis and setup controls remain locked while the download is pending.

  5. Wait for “Download finished”.

    The inventory refreshes. Confirm availability before analysis.

Recovery: for “Download failed”, inspect the error. Check terms/access, network, disk space and local Ollama. Retry with an explicit download action. The app has no download-cancel endpoint; closing the page does not confirm cancellation.

Set up an optional HTTP model service

Read the provider links and Provider configuration (English). Obtain upstream access approval and permitted weights. Check hardware and dependencies. Start the provider’s compatible local service at its configured loopback URL, then select Refresh model availability. A healthy service can become available. The app does not install those services or bypass gated access.

Read the rough remaining estimate

Rough remaining estimate starts with workstation guesses: 1–60 seconds for the HU baseline and 1–15+ minutes for vision models. Later estimates use recent local request durations for the same model and requested image count. Only numeric duration history is saved in this browser; no study identifiers are stored with it.

A batch adds estimates for remaining available models. If the upper estimate is exceeded, the UI says Taking longer than estimated; still running. Hardware, input size, cold loading and generation can extend the wait. These are guesses, not measured benchmarks, guaranteed deadlines or inference-progress percentages.

Continue an interrupted limited run

Prerequisites: the original new-format invocation, unchanged experiment/limit, code/commit, dependency lockfile, data/index/split, prompts/model settings and runtime weights. Vision/HTTP services must expose a known matching model digest. Identity checks may take time before progress appears.

  1. Locate the original Invocation: directory.

    Use its final folder name in place of PASTE_PRINTED_RUN_ID below.

  2. Run with the same experiment and limit.
    uv run thoraxbench benchmark \
  configs/experiments/E000_heuristic_hu_baseline.yaml \
  --limit 2 --resume data/results/benchmark/E000/PASTE_PRINTED_RUN_ID

Checkpoint: a complete validated run returns existing aggregates without inference or rewriting. An interrupted in-flight unit may run again; a case file absent from the checkpoint may be an orphan and is not automatically reused.

Recovery: changed identity, invalid checksums, an unknown model digest, a symlink escape or an active writer refuses resume. Preserve the evidence. Resolve the cause or start a new invocation; never edit checksums to force reuse. Legacy runs without checkpoints cannot resume.

Compare methods before metrics. Missing presence/confidence remains unavailable. Zero available requested-label predictions abstain; partial coverage never invents negatives. Task E reports omissions and coverage. Task G excludes abstained/unknown decisions and exposes its eligible reassurance denominator. Current prompts use one-based image captions. Historical results were not recomputed under these changes.

Available dataset/split/reference hashes, scoring/schema source and input hashes (HU bytes/geometry plus prepared input) identify the setup. Missing sources remain unavailable; hashes do not validate labels. Selected direct header values and paths are redacted from output text/metadata, including cached-study analysis. This is not OCR or anonymity; source-unavailable caches cannot recover identifying header values.

  2. Select “Open” on a complete run.

13 / EVIDENCE RELIABILITY

Check the inputs. Keep uncertainty.

Research use only. This self-made experimental tool may be incorrect, incomplete or misleading. It is not professional medical advice or a basis for diagnosis or treatment.

Understand which image number is cited

Vision-model evidence uses one-based attached-image numbers: Image 1 is the first prepared image. A source-slice position in a caption is not an attached-image number. The HU baseline instead uses zero-based source-slice indices for its explanatory previews.

New constrained Ollama runs with P2–P4 remove invalid or duplicate image references. A default-positive prediction (implied presence probability at least 0.5) without valid attached-image evidence becomes unavailable before scoring. If no requested predictions remain available, the run abstains. The raw response remains inspectable. An in-range number still does not prove visible support.

Separate visual output from heuristic context

The versioned multi-slice view parameter include_cues defaults to true. Set it to false in model YAML view_params or experiment view_overrides to omit heuristic prompt text. The images and sampling remain unchanged. Use YAML booleans only; null, numbers and strings are refused. View hashes and recorded context distinguish this ablation. Preprocessing still computes cues for sampling; this is not a speed comparison.

Prerequisites: locked environment, approved split/index, installed Q4 tag and local Ollama. Use calibration cases only. Run from the repository root:

uv run thoraxbench benchmark \
  configs/experiments/E001_cue_ablation.yaml --limit 1
  1. Keep the case bound.

    The YAML does not enforce --limit 1. This selects at most one calibration case per dataset and runs two sequential variants.

  2. Inspect actual prepared-image counts.

    Anatomy sampling retains landmarks and can exceed its target. Both variants must use identical image hashes.

  3. Read both responses and warnings.

    Compare omitted labels, unsupported positives, failures and abstentions. Do not infer correctness from confidence or agreement.

  4. Preserve the invocation folder.

    Requests, responses, provenance and checkpoints stay under ignored data/results/benchmark/.

17 / LOCAL DIAGNOSTICS

See the work. Inspect a header. Keep a trace.

Research use only. This self-made experimental tool can be incorrect or incomplete. It is not medical advice or a diagnosis.

Follow loading

Jobs show path/header checks, DICOM discovery, pixel decoding, input QC and source recheck. Counters report actual work in that operation. Path checks count entries; image/header passes count files; QC counts checks. Totals can be unknown. Counters restart between passes and are not an overall percentage or remaining-time promise.

Inspect exactly one file

Run from the repository root. Replace the quoted path with one file on your computer. No suffix is required.

uv run --no-sync python scripts/dcom_evaluator.py "/absolute/path/to/one/file"

The default reads headers only. JSON includes technical metadata and unreadable tag numbers, VRs and byte lengths. It omits identifying values, paths, raw bytes and raw error text. Exit 0 means header conversion succeeded; exit 2 means the report found a problem. Inspect output before sharing; this is not an anonymization guarantee.

Append --check-pixels only for an explicit local decoder test. It prints shape/type, never pixels. Sealed inputs and corrupt headers cannot enable pixel decoding. No sibling files are scanned.

Scan a folder; then request a full import check

Run from the repository root. This default folder scan reads headers only, groups errors and reports opaque series summaries. It does not decode pixels, run models or export images.

uv run --no-sync python scripts/dcom_evaluator.py --scan-headers "/absolute/path/to/folder"

Bounds default to 10,000 files and 300 seconds; use --help for limits and --progress for aggregate stderr counters. Exit 0 means a complete scan, even with unreadable headers. Inspect counts, error groups and eligibility. Exit 2 includes truncated or failed scans; correct the input or choose explicit bounds before retrying.

For explicit local pixel loading and application input QC, run:

uv run --no-sync python scripts/dcom_evaluator.py --scan-headers --check-import "/absolute/path/to/folder"

Full import runs only after a complete scan. It starts no model and creates no image/report export. Inspect the import result and QC. Readable headers do not prove usable pixels or model accuracy. Review JSON before sharing; this is not anonymization.

Vendor private values that pydicom mistypes, such as a 6-byte ELSCINT1 (01F1,1026) Pitch, are kept as raw bytes instead of rejecting the slice. private_values_raw counts them; they remain in error groups but are informational. Public tags stay strict. qc_warning_count counts input-QC warnings.
