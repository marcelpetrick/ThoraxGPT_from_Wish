# LinkedIn promo — "A chest CT on a CD" (40 seconds)

**Goal:** a calm, inviting 40-second preview that makes people curious enough to try
ThoraxBench Local on their own chest CT, and shows where to get it. It tells the story the
project started from: a friend had his chest CT on a CD and no report yet.

**Deliverable:** `media/promo-16x9.mp4` (1920×1080, 30 fps, exactly 1200 frames, H.264 +
AAC voice-over and music, about -16 LUFS), with `promo-16x9.srt`, a thumbnail and
`promo-credits.txt`. No upload is authorized; the user posts it.

Design rules came from the user's review of the first draft (too fast, over-cropped,
cartoon phantom, file list instead of README): few long shots with soft fades, the real app
window (only the browser bar is hidden), at most a slow 2–4 % push-in, one caption per shot,
a realistic CT, and the rendered README with a green CI badge.

## Data, honesty and credits

- **CT:** the public, de-identified LIDC-IDRI calibration case `LIDC-IDRI-0027` (TCIA,
  CC BY 3.0), chosen by the user on 2026-10-20 instead of the drawn phantom. Never the
  user's private scan. The recorder refuses non-calibration cases (`CaseGuard`) and
  narrows the browser library to this one case.
- **Model run:** real `monai-lung-nodule` full review; nothing is mocked. Its LUNA16
  training data is derived from LIDC-IDRI, so the example overlaps the training data — the
  end card and credits say so. It is an illustration, not accuracy evidence.
- **Speed-up:** the only sped-up shot carries its real duration on screen.
- **Voice:** Kokoro-82M (Apache-2.0), voice `af_heart`, generated locally. The final audio
  was transcribed back with faster-whisper to confirm every line is intelligible and in
  its shot. **Music:** a pad generated by the renderer (no third-party recording).
- **Disclaimer:** once, on the end card ("Research tool, not a diagnosis.").

## Procedure

1. **Rehearse and capture** (about 3 minutes; needs network for the GitHub page and a green
   CI badge):

   ```bash
   uv run --extra detector python scripts/promo_video.py capture \
     --dataset lidc_idri --case LIDC-IDRI-0027 --allow-real-calibration --chromium /usr/bin/chromium
   ```

   One continuous 2560×1440 Xvfb recording of a kiosk Chromium at 1.5× page zoom, mouse
   hidden, with timestamped scene events and element boxes. Takes stay under ignored
   `data/results/promo/`; failed takes are kept.
2. **Voice:** generate `line-0.wav` … `line-6.wav` with Kokoro (`af_heart`, speed 0.92) in
   a separate environment; on this workstation the bundled espeak library needs the system
   `libespeak-ng` instead.
3. **Cut plan:** `cut-plan.json` in the take folder lists cards and shots (source offset,
   duration, speed with a mandatory `speed_tag`, push, caption, voice line, optional
   highlight box). `validate_plan` refuses plans that run off the master, hide a speed-up,
   miss the exact length or crop into the browser bar.
4. **Render:**

   ```bash
   uv run --extra detector python scripts/promo_video.py render \
     --take data/results/promo/<take> --voice <folder with line-N.wav>
   ```

   Output, SRT, contact sheet, thumbnail, credits and an FFprobe record land in a new
   `render-*` folder; frames, the AAC stream and the frame count are checked.
5. **Review** like a viewer: contact sheet, full-size frames per shot, loudness
   (`ebur128`), transcript. Commit only the reviewed cut to `media/` and pin its SHA-256 in
   `scripts/check_no_medical_data.sh`.
