# P6: single-image reasoning and binary answer

Research use only. This self-made experimental tool may produce incorrect, incomplete or
misleading findings. It is not professional medical advice or a basis for diagnosis or
treatment decisions.

P6 is a local adaptation of the one-condition reasoning protocol discussed in
[the approach review](approach-review-2026-10-17.md). It does not establish parity with
Google's Hugging Face runtime or official evaluation. It uses a strict single-image
fallback because reliable multi-image citation binding has not been established.

Run commands from the repository root. Use the configured local Ollama tag after its terms
have been acknowledged. This command does not download weights:

```bash
uv run python scripts/probe_p6.py --window both
```

The bounded diagnostic uses matched synthetic sphere/control crops and one condition,
with separate outputs under ignored `data/results/p6-probe/`. It does not read real studies.
Its latest four answers were all yes: both window readiness gates failed. See
[the usage review](model-usage-review-2026-10-17.md).

The dedicated model configuration selects one uniformly sampled axial image, 896 px,
MedGemma RGB, no MIP, no coronal image and no heuristic context. One image is a limited
view of a study. Its answer is not a whole-study negative finding or a detection result.
For candidate work, pass one image from a physically defined candidate crop directly to
the same adapter. Do not substitute a reference-selected crop into a detection claim.

For each requested canonical condition, the adapter sends an independent visual request
with at most 192 generated reasoning tokens. The argument must end with an explicit
`Final Answer: yes` or `Final Answer: no`. It then sends that argument as text to a separate
call constrained to the JSON string `"yes"` or `"no"`, with at most 16 generated tokens.
The second call has no images. Its score reflects classification of the argument, not a
new visual judgement. Both requests and complete provider responses remain in provenance;
recorded requests replace pixels with image SHA-256 values.

P6 requests the top 20 answer-token logprobs on the second call. A score is available only
when both yes and no alternatives have finite observed logprobs. Missing alternatives,
missing final answers, contradictory extracted answers, malformed responses, provider errors and token-limit stops remain
explicitly unavailable. Never replace a missing score with a guessed 0/1 or self-reported
confidence. The common findings schema encodes the conditional score through the verdict's
confidence field; it is an uncalibrated score, not validated certainty.

The protocol keeps categorical answers and probability scores separate. `nonconstant_readiness`
in `adapters/p6.py` requires complete scoring, both reference classes, nonconstant categorical
answers and score AUROC above 0.5 on calibration examples. This is a descriptive readiness
gate, not evidence of generalization or a substitute for clinical evaluation. A constant
categorical answer can fail while its score still shows a signal.

Checkpoint: the normal analysis path prepares exactly one image. The output records P6
prompt hash, protocol version/options, per-label answers, errors, both provider calls and
`sole prepared input; no model-returned citation`. Findings contain no fabricated image
numbers. The protocol rejects zero or multiple prepared images; it never silently changes
layouts or falls back to another prompt.

Recovery: inspect per-label diagnostic reasons and raw responses under the ignored results
directory. Use a complete calibration-only experiment for readiness decisions. Keep
internal-test and sealed data out of protocol tuning. P0–P5 retain their existing behavior.
