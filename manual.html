01 / PREFLIGHT

Install. Verify. Start locally.

Use a terminal on the computer that will run the software. The commands below assume a source checkout and uv. Replace the example path with your checkout path. If uv is missing, follow the official uv installation instructions first.

  1. Open the repository directory.
    cd /home/mpetrick/repos/ThoraxGPT_from_Wish
  2. Install the locked Python environment.
    uv sync --frozen --all-groups

    Python 3.14 or newer is required. uv can provision the requested Python environment. Initial installation needs package access; inference stays local.

  3. Check the installed command.
    uv run thoraxbench --version
uv run thoraxbench --help

    Expect a version, the research disclaimer, and the command list.

  4. Start the workbench.
    uv run thoraxbench serve

    Leave this terminal open. Open http://127.0.0.1:8000 on the same computer.

Checkpoint: The Analysis page appears in English and light mode. The page shows the research disclaimer. A new installation may have no studies yet. This is expected.

Required for the demo

A supported Python environment, the locked dependencies, a browser, and enough free disk space for synthetic data and outputs.

Optional for vision models

A local Ollama installation and compatible model weights. The deterministic heuristic-hu baseline works without them.

Port 8000 is already in use

uv run thoraxbench serve --port 8001

Open http://127.0.0.1:8001. The server binds to loopback. LAN access and remote inference are not supported in this MVP.

02 / NORMAL PROCEDURE

Complete your first browser run.

Create demo → Inspect study → Run locally → Review → Export
  1. Select “Create synthetic demo”.

    Expect a synthetic study with 64 axial slices. It contains simulated nodule and fluid-density regions. The images contain no patient data.

  2. Inspect the study viewer.

    Move the slice slider. Use the Left and Right arrow keys when the slider has focus. Change the display window to Lung, Mediastinum, Bone or Abdomen. Window changes affect the viewer only.

  3. Select “heuristic-hu” as the model.

    This baseline uses HU-volume measurements. It sends no rendered images to a vision model. The image-count control does not affect its predictions.

  4. Select “Run analysis locally”.

    Wait for a completed result or explicit failure/abstention. “Browser request elapsed” shows waiting time, including loading, inference and reporting. It differs from recorded “Engine stages”. Expect synthetic nodule and effusion findings.

  5. Read the status before you read the findings.

    Check study quality, the finding table, severity/review context and the English research report. Follow the interpretation checklist on the next page.

  6. Select “Download HTML”.

    Open the saved file in a browser. Check the findings and embedded image gallery. Also save JSON for structured output and “Download report” for Markdown.

Checkpoint: The HTML report opens after you stop the server. It needs no external images, fonts, scripts or internet access. Missing evidence references remain explicit.

Optional: compare the recommended local models

Enable “Compare recommended local models”, then select “Compare local models”. Available heuristic-hu, MedGemma Q4/Q8, Gemma 3 and Qwen3-VL run sequentially; unavailable models are skipped. “Batch progress” shows the current model, not inference percent. Save per-model downloads and “Download comparison HTML”. See model setup and rough wait estimates before a longer run.

Keyboard help and preferences

Use Tab to reach controls and help-bearing fields. Focus or hover shows translated help; Escape dismisses it. The language switch selects English or German. The theme switch selects light or dark. Both choices persist in this browser. Reports and prompts remain English. About lists the author, version and library licenses.

Privacy checkpoint: A downloaded report contains images and research identifiers. Keep real-study exports in controlled local storage. The browser may save downloads outside the repository; manage those copies as sensitive data.

03 / RESULT REVIEW

Inspect claims before conclusions.

Check every claim against evidence. The software cannot establish health, care needs or a diagnosis.

Read firstWhat it meansOperator action
CompletedThe engine returned output. This does not validate it.Inspect QC, findings, evidence and provenance.
Abstained / failedNo usable research reading is available.Read the reason. Preserve the failed run. Do not interpret it as “nothing found”.
Present / not detected / uncertainThe model's reported presence status.Treat negative and uncertain output as fallible.
Presence scoreUncalibrated support for presence; not measured accuracy.Do not treat 0.79 as a validated 79% probability.
Severity / typical attentionEducational reference context, not validated triage.Check its assumptions and sources. Do not derive personal medical instructions.

Severity and “should this be checked?”

The reference scale runs from incidental → low → moderate → high → critical. Typical attention uses routine, soon, urgent, emergency. These describe general reference knowledge for a reported label. They do not establish the severity or urgency of an actual person's condition.

No automatic clearance: An absent, low-rated, unknown or uncertain finding does not establish that no professional review is needed. The tool cannot answer whether a person should be checked. Its output is not advice from a healthcare practitioner.

Check image evidence

  • Vision-model reports show the actual prepared input images. Image 1 is the first model image. A sampled image set may miss other parts of the study.
  • Heuristic reports show illustrative source-slice previews. Their source indices start at 0; they are not vision-model inputs.
  • An evidence link is a reported association, not verified localization or a segmentation. Invalid or missing references must remain unresolved.

Compare models without implying consensus

Compare each model column by finding, status and uncalibrated score. Keep abstentions, failures and skipped models visible. Agreement is not validation; disagreement is not an accuracy ranking. Use each model’s downloads to inspect its own images and provenance. A combined offline HTML report preserves the comparison and individual evidence reports.

Check reproducibility

Save JSON for original responses, QC, hashes and provenance. “Browser request elapsed” covers waiting time for the request or batch; “Current model elapsed” times the active model. “Engine stages” exclude loading and reporting. Timers do not measure inference progress. Synthetic runs and transport tests do not establish patient accuracy.

04 / COMMAND-LINE PROCEDURE

Repeat a run and save its artifacts.

Run these commands from the repository root. Keep the working directory unchanged between steps. These examples use only synthetic data.

  1. Create a fresh synthetic study.
    uv run thoraxbench demo-data data/demo/manual
  2. Run the deterministic baseline.
    uv run thoraxbench analyze data/demo/manual \
  --model heuristic-hu \
  --output data/results/manual/result.json \
  --report data/results/manual/report.md \
  --html data/results/manual/report.html
  3. Open the saved HTML file.

    Open data/results/manual/report.html in your browser. Inspect the matching JSON and Markdown files in the same folder.

Checkpoint: A successful run returns exit status 0. A failed run or abstention returns a nonzero status. When a result exists, saved artifacts explain the abstention. Failures before result creation may produce only an error message.

Optional: run a local vision model

First check availability. A configured model is not necessarily installed, licensed for your intended use, or accurate.

uv run thoraxbench models
uv run thoraxbench analyze data/demo/manual \
  --model medgemma1.5-q4 --n 4 \
  --output data/results/manual/vision.json \
  --report data/results/manual/vision.md \
  --html data/results/manual/vision.html

The model must already exist in local Ollama. Larger image requests may take minutes. Empty predictions, truncated output, invalid responses and unsuitable inputs can cause abstention.

Available overrides

--model selects an ID from configs/models/. --prompt selects P0–P4. --strategy overrides the sampling strategy. --n requests a positive number of sampled slices; the browser limits it to 1–16. Use uv run thoraxbench analyze --help for the current options.

HTML output must be inside the configured data directory's results/ folder. Destinations or symlinks that escape that folder are rejected before inference. JSON and Markdown examples also stay inside ignored results storage.

Model setup

  1. Inspect the model YAML.

    Find its adapter, tag, view and prompt under configs/models/. Example: medgemma1.5-q4 expects Ollama tag medgemma1.5:4b-it-q4_K_M.

  2. Check model terms and hardware needs.

    See docs/model_cards.md and docs/model_selection.md. A model ID is not a download guarantee. Gated terms remain separate from dataset licenses.

  3. Start the local model service.

    If Ollama is installed but not running, start it using your local installation's service controls or ollama serve. If it is already running, use that instance.

  4. Check the installed tags.
    ollama list
uv run thoraxbench models

Configuration files, prompts, preprocessing and sampling affect results. Preserve version control and the recorded hashes. Remote/LAN inference is a design proposal only; do not bypass the loopback guard.

06 / MODEL SETUP & WAIT ESTIMATES

Install explicitly. Expect variable waits.

Open Model availability & setup. Check availability, adapter, license and provider information. “Available” means the local runtime responds; it does not establish accuracy, GPU capacity or useful predictions.

Download a configured Ollama model

Prerequisites: running loopback Ollama, network access and enough space in its model store. Weights are stored by Ollama, outside this repository’s data folder.

  1. Open “Model terms”.

    Check the publisher’s terms and any access requirements.

  2. Check “I reviewed and may comply with the applicable model terms”.

    Acknowledge this only when the terms permit your use.

  3. Select “Download model weights”.

    The app asks local Ollama to pull that configured tag. Downloads never start automatically.

  4. Inspect “Model download”.

    “Active layer bytes” reports actual current-layer bytes. It can reset between layers; it is not a whole-model percentage. Analysis and setup controls remain locked while the download is pending.

  5. Wait for “Download finished”.

    The inventory refreshes. Confirm availability before analysis.

Recovery: for “Download failed”, inspect the error. Check terms/access, network, disk space and local Ollama. Retry with an explicit download action. The app has no download-cancel endpoint; closing the page does not confirm cancellation.

Set up an optional HTTP model service

Read the provider links and Provider configuration (English). Obtain upstream access approval and permitted weights. Check hardware and dependencies. Start the provider’s compatible local service at its configured loopback URL, then select Refresh model availability. A healthy service can become available. The app does not install those services or bypass gated access.

Read the rough remaining estimate

Rough remaining estimate starts with workstation guesses: 1–60 seconds for the HU baseline and 1–15+ minutes for vision models. Later estimates use recent local request durations for the same model and requested image count. Only numeric duration history is saved in this browser; no study identifiers are stored with it.

A batch adds estimates for remaining available models. If the upper estimate is exceeded, the UI says Taking longer than estimated; still running. Hardware, input size, cold loading and generation can extend the wait. These are guesses, not measured benchmarks, guaranteed deadlines or inference-progress percentages.

07 / RESEARCH COHORT

Acquire under the gates. Audit the headers.

Run these commands from the repository root. Prerequisites: network access to TCIA, and a dataset whose registry status is approved*. Check it with uv run thoraxbench datasets. The pilot cohorts lidc_idri and nsclc_radiogenomics are already acquired and split.

Acquire an approved TCIA collection

  1. Show the plan and the budget verdict.
    uv run thoraxbench acquire <id> --dry-run --patients 20

    Nothing is downloaded. Read the series counts, the size estimate, the data/ usage and fits.

  2. Start the download with the same options.
    uv run thoraxbench acquire <id> --patients 20

    To resume, re-run without --patients. Complete series are skipped.

  3. Re-hash the stored files.
    uv run thoraxbench acquire <id> --verify

    After a split exists, only development patients are opened and hashed.

  4. Freeze the patient split before indexing.

    Follow page 10.

Checkpoint: exit status 0. data/raw/<id>/ holds the DICOM series, _sha256.txt, _acquisition.json and a license snapshot.
Observed problemRecovery action
Exit 2: Acquisition refusedA license, series-license, split or budget gate failed. Fix the registry entry or the plan. Never edit a license status to pass the gate.
REFUSED: exceeds the data budgetLower --patients for a new selection, or free space.
Exit 1: download or checksum failureRe-run later. For an incomplete or mismatched series, remove only that series directory and re-run.

Audit DICOM headers for identifiers

uv run thoraxbench privacy audit data/demo/manual

The audit prints tag keywords and file counts, never values. Add --json for structured output. Add --strict to exit with status 1 on a fail item.

Checkpoint: the synthetic phantom reports FAIL for PatientName (a synthetic name) and three review items. Recovery: if a real study reports fail, do not analyse or share its outputs until the identifier source is understood. The audit does not inspect pixel data and does not prove anonymity.

08 / DEVELOPMENT BENCHMARK

Score development cases. Keep the holdout sealed.

Prerequisites: the datasets named in the experiment are split and indexed. Experiments live in configs/experiments/: E000 is the deterministic HU-heuristic baseline; E001–E004 need MedGemma in local Ollama.

  1. Run a quick check on a few cases per dataset.
    uv run thoraxbench benchmark \
  configs/experiments/E000_heuristic_hu_baseline.yaml --limit 2
  2. Run the full experiment.
    uv run thoraxbench benchmark \
  configs/experiments/E000_heuristic_hu_baseline.yaml
  3. Read the report at the printed Report: path.

    Each invocation creates a unique folder under data/results/benchmark/<experiment-id>/. Open result.json in that same folder for structured output.

  4. Compare the printed config SHA-256 with docs/results.md.

    A different hash means the experiment file changed. Record a new run; do not overwrite the old entry.

Run folders use <timestamp>-<hashprefix>-<uuid>. Repeated or limited runs preserve earlier outputs, including legacy flat files. The experiment's labels select both requested and scored findings. Prompt precedence is variant, experiment, model configuration, then P3.

Checkpoint: the command prints status counts per variant, the result and report paths, and the config SHA-256. Only development cases are read. Failures and abstentions stay explicit per case and are excluded from label metrics.
Observed problemRecovery action
Exit 1: Benchmark failedRead the named cause, for example a missing split or index. Freeze and index the dataset first.
Exit 2 after --unsealExpected. Sealed evaluation is not implemented. Run without --unseal.
Vision model unavailableCheck uv run thoraxbench models and local Ollama. Do not substitute a cloud endpoint.

09 / ABNORMAL PROCEDURES & SHUTDOWN

Stop safely. Keep the holdout sealed.

Before any real-study workflow

Verify the specific dataset's license status with uv run thoraxbench datasets. Acquisition requires an approved registry entry; never infer a license from the hosting site. Acquire the cohort first (page 08).

  1. Freeze the patient split before indexing or analysis.
    uv run thoraxbench split lidc_idri

    Run this only for an approved, already downloaded cohort that has no split yet. Existing frozen splits refuse replacement. Do not regenerate them.

  2. Index only permitted development cases.
    uv run thoraxbench index lidc_idri --limit 1

    Indexed development studies appear in the browser. The browser has no arbitrary-folder upload flow. The CLI can read a permitted study directory through its guards.

Never open data/sealed/, inspect holdout images, or copy sealed cases into development folders. No current command evaluates the holdout. thoraxbench benchmark --unseal is refused; sealed evaluation is not implemented.

Observed problemRecovery action
Model unavailableOpen Model availability & setup. Check ollama list, the configured tag and loopback URL. Use heuristic-hu for the demo. Do not substitute a cloud endpoint.
Slow run / empty or invalid outputPreserve the error and result. Try a smaller synthetic vision request. Do not turn an abstention into a negative finding.
Study missing / guard rejectionCheck the development split and index. A holdout rejection is intentional. Do not bypass it.
Disk full / cannot writeCheck df -h . and du -sh data. Review disposable generated results/caches before removing anything. Preserve raw data, manifests and split files.
Old download link stops workingDownload links are registered for the running server process. After restart, open the saved files under data/results/ui/ directly or rerun the study.

Shutdown and handover

Press Ctrl+C in the server terminal. Completed result files remain on disk. Record the model, settings, version, result paths, warnings and next action before you hand work to another researcher. Never commit patient images, rendered CT slices, model weights or secrets.

Maintain this manual: edit manual.html, then regenerate the PDF from the repository root with uv run python -m playwright pdf --paper-format A4 file://"$PWD"/manual.html manual.pdf. Install Chromium with uv run playwright install chromium if needed. Check docs/plan.md for current scope; this manual contains no patient images.
